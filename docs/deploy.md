# Как выложить Detective в сеть

Игра это обычный Node-сервер (Express и Socket.IO) без сборки. Нужен хостинг, который держит постоянно запущенный процесс и пропускает WebSocket. Статичные хостинги вроде GitHub Pages не подойдут: партия живёт в памяти сервера.

## Что понадобится

1. Аккаунт на хостинге (проще всего Render, Railway или Fly.io, подойдёт и обычный VPS).
2. Код в репозитории на GitHub (хостинг забирает код оттуда). Архив с кодом лежит в `releases/`.
3. Домен или бесплатный адрес от хостинга. Адрес должен быть с https, иначе не заработает вход через Discord и Google.
4. Для входа через Discord и Google: зарегистрировать приложения у провайдеров (шаг 5).

## Вариант А: PaaS (Render, Railway, Fly.io), примерно полчаса

1. Создайте репозиторий на GitHub и загрузите туда содержимое архива (без `node_modules` и `data`).
2. На хостинге создайте новый Web Service из этого репозитория.
   - Окружение: Node 22 или новее.
   - Команда установки: `npm install`.
   - Команда запуска: `npm start`.
   - Порт: хостинг сам передаёт переменную `PORT`, код её читает.
3. Подключите постоянный диск (Persistent Disk или Volume) и укажите путь к нему в `DATA_DIR`, например `/data`. Там лежат архив дел, статистика сезона и ключ подписи сессий. Без диска всё это сбрасывается при каждом перезапуске.
4. Задайте переменные окружения:
   - `ADMIN_KEY` пароль админки (придумайте длинный, он защищает редактор дел);
   - `PUBLIC_URL` адрес сайта с https, например `https://detective.example.com`;
   - `DISCORD_SERVER_URL` приглашение на ваш Discord-сервер (появится строка «Нет компании?» на главной);
   - позже `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
5. Запустите. Откройте `https://ваш-адрес`, зайдите в `/#/admin` с вашим `ADMIN_KEY` и проверьте тестовую комнату.

## Вход через Discord и Google (можно позже)

Без него игра работает по нику, и это нормально для начала.
- Discord: https://discord.com/developers/applications, новое приложение, OAuth2, добавьте Redirect `PUBLIC_URL/auth/discord/callback`, скопируйте Client ID и Secret.
- Google: https://console.cloud.google.com, APIs & Services, Credentials, OAuth client ID типа «Веб-приложение», в Authorized redirect URIs добавьте `PUBLIC_URL/auth/google/callback`.
- Впишите значения в переменные окружения и перезапустите. При старте сервер печатает точные адреса возврата.

## Вариант Б: свой VPS

1. Арендуйте VPS (Ubuntu), поставьте Node 22 и git, склонируйте репозиторий, выполните `npm install`.
2. Запустите под менеджером процессов: `ADMIN_KEY=… PUBLIC_URL=https://домен DATA_DIR=/var/detective npm start` (удобно через pm2 или systemd).
3. Поставьте перед ним Caddy или nginx с HTTPS и проксированием на порт 3000. WebSocket должен проходить (в Caddy это работает из коробки, в nginx нужны заголовки Upgrade).
4. Направьте домен на IP сервера.

## Важные ограничения

- **Один экземпляр.** Комнаты и партии хранятся в памяти процесса, поэтому запускайте ровно один сервер, без балансировки между несколькими.
- **Перезапуск сервера обрывает идущие партии.** Архив дел, статистика и сессии сохраняются на диске. Выкатывайте обновления, когда никто не играет.
- **Нагрузка.** Один небольшой сервер спокойно держит десятки комнат.
- **Голос.** Игроки говорят в Discord, сайт голос не передаёт.
